## 1. 제품 명제

trdr는 **에이전트 퀀트 개발의 인프라 일체**를 제공한다 — 브로커 비종속,
로컬 우선, 데이터·엔진·상태를 사용자가 소유한다.

| 기둥 | 내용 | 대체재 대비 (2026-08 조사) |
|---|---|---|
| 1 데이터 | 믿을 수 있는 로컬 데이터셋: 상폐 포함, 수급 이력, 전 행 출처 라벨 | 통합·출처 라벨·로컬 소유 조합은 인컴번트 0. KRX 2025-12 잠금으로 DIY는 더 취약해짐 |
| 2 엔진 | 시장 현실 비용(거래세·호가단위·가격제한) 내장 결정론 백테스트 | 이 조합을 오픈 엔진으로 제공하는 곳 전무 |
| 3 콕핏 | 사람과 에이전트가 같은 상태를 보는 화면 + 자유 구성 대시보드 | 브로커 MCP는 흔해지는 중 — 차별점은 비종속·소유 |

정직성 규율(사전등록·검증·결과)은 이 기반 위의 **차별화 층**이다. 첫 사용
이유가 아니다.

시장: v0는 한국 한정. 단 캘린더·비용 모델·호가 규칙·데이터 소스는 **시장
팩**으로 분리 설계해 글로벌 확장을 열어둔다.

플랫폼: v0는 **macOS 전용**. Windows·Linux는 구조 여지만 두고 빌드·검증·
문서화하지 않는다. 자격증명은 **keychain 전용** — 모든 API 키·시크릿은
macOS Keychain으로만 다루며, 환경변수·평문 설정·세션 출력에 값이 노출되지
않는다 (키 이름 표시는 가능, 값은 불가. kis·dart CLI의 검증된 방식 승계).

## 2. 사용자와 루프

v0 사용자는 1명 — user zero(relationship-explorer 연구 워크플로). 잠재
사용자는 화면 요구사항(1080p 검수, 결과 이미지)으로만 반영한다.

| 루프 단계 | 행위자 | 도착 화면 |
|---|---|---|
| 가설 제시 (자연어) | 사용자 | 터미널 pane·명령줄 에이전트 모드 |
| 스펙 형식화 (.trdr.yaml) | 에이전트 | 파일시스템 → 스펙 pane 핫리로드 |
| 탐색 백테스트 | 에이전트 또는 명령줄 | 차트 오버레이·백테스트 리포트 |
| 사전등록 확정 | **사용자 전용** | 등록 화면 (GUI 클릭만) |
| 검증 | 앱 (2모드, §5) | 관찰 pane·결과 리포트 |
| 결과 → 검증 기록 | 앱 자동 | 검증 기록 화면 |

루프 범위는 전략 수립·검증까지다. 주문·실행은 v0에 존재하지 않는다
(관찰은 무집행 추적).

**v0 인수 기준**: relationship-explorer의 실제 전략 1개가 trdr 안에서만 이
루프를 완주한다 — 만든 우리가 수제 스크립트를 버리고 갈아탈 수 있으면 합격.

## 3. 용어

원칙: **절차의 무게는 시각(도장·해시·카운트다운)으로, 용어는 일상어로.**
전문어는 문서·코드에만. 정본 용어집은 w-bgzxp 첨부(glossary v1).

수명주기 한 줄: **탐색 → 사전등록 → 검증 → 관찰 → 결과.**
주요 대응: 검증 기록(registry) · 결과(verdict) · 재현 검증(deterministic
replay) · 단축 명령(mnemonic) · 시장 팩(market pack). 앱 셸은 무명(콕핏 폐기).

## 5. 정직성 규율 요구사항

프레이밍 규칙: 사전등록은 **자기 기만을 막도록 돕는 장치**다 — "전략을
하나의 고정 해시로 만들어 정직하게 테스트하라는 제안". 봉인·차단·강제
어휘는 제품 문구와 문서에서 쓰지 않는다. 접근 통제 주장 금지 (로컬
데이터는 누구나 볼 수 있다 — 보증하는 것은 기록 규율과 재현 검증뿐).

| 요구사항 | 도착 화면 |
|---|---|
| 등록 시 잠기는 것(스펙 해시·시각·검증 구간)을 전부 보여주고 확정받는다 | 등록 화면 |
| 확정 버튼은 GUI 사람 클릭만 — CLI·에이전트는 초안 준비까지 | 등록 화면 |
| 검증 2모드: ①과거 검증(holdout, 결과 즉시) ②실전 관찰(D-0 카운트다운) | 등록 화면(모드 선택)·관찰 pane |
| 결과 리포트에 검증 모드 라벨 — 두 모드의 증거 무게 차이를 표시 | 결과 리포트 |
| D-0 이전 지표에 "참고용" 라벨 강제 | 관찰 pane |
| 재등록 시 계보 자동 연결, 결과 리포트에 재등록 이력 노출 | 검증 기록·결과 리포트 |
| 모든 결과에 출처 라벨(데이터 소스·기간·보정) + 재현 검증 해시 | 결과 리포트 |
| 축하·애니메이션 없음. 노이즈 결과도 동일한 무게로 표시 | 결과 리포트 |

열린 항목: 사전등록되는 검정 방법의 명명·표기(엔진 설계에서 확정),
재등록 계보의 시각 표현(목업 v2에서 확정).

## 6. 인터랙션 계약

### 6.1 명령줄 (앱 내)

- 문법: `[티커] [명령] [인자]`. 티커만 = 차트. 명령만 = 현재 컨텍스트 적용.
- 한국어 1차 + 영문 별칭 + 한영 오타 보정. Tab = 같은 입력창이 에이전트
  프롬프트로 전환.
- v0 명령 9개: 차트(ch) 수급(flow) 스펙(spec) 백테스트(bt) 등록(reg)
  관찰(obs) 기록(hist) 수집(data) 설정(cfg).

### 6.2 에이전트 인터페이스 — CLI 우선, MCP 없음

에이전트는 **trdr CLI + 파일시스템**으로 조작한다. MCP 서버는 v0에 없다
(필요 시 CLI 위 얇은 어댑터로 추후 추가).

| 에이전트 가능 (CLI·파일) | 에이전트 불가 |
|---|---|
| 스펙 파일 읽기·쓰기 (파일이 정본, 저장 시 앱 핫리로드) | 사전등록 확정 (GUI 사람 전용) |
| 백테스트 실행·결과 조회 | 검증 기록 삭제·수정 (누구도 불가) |
| 데이터셋 조회·수집 트리거 | API 키 등록·변경 |
| 실행 중 앱에 차트 명령 전달 (로컬 소켓 경유 CLI) | 주문 (v0에 없음) |
| 등록 초안 준비, 검증 기록·관찰 상태 읽기 | |

동작 일치 원칙: 명령줄·CLI·GUI는 같은 백엔드 동작을 공유한다 — 사람이
치는 것과 에이전트가 호출하는 것이 같은 함수다.
