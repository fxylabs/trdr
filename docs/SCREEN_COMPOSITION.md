# trdr v0 화면 구성안

> 작성 2026-08-07. 근거: docs/SCREEN_ACTIONS.md §2(개체·질문·리드 규칙) 위에서,
> 2026-08-07 구성 논의의 결정 6건 — 01kzdr2d(KRX 비공식), 01kzdr99(플러그인
> 표면), 01kzdwff(성장 규칙), 01kzdwfq(헤더 2층), 01kzdxn9(2화면 분리),
> 01kzdxng(리플레이 지평·가상 포지션·일 단위).
>
> 이 문서는 SCREEN_ACTIONS(무엇이 있고 눌리면 무슨 일이 나는가)와 목업
> (어떻게 보이는가) 사이의 층이다 — **화면마다 어떤 pane이 어떤 크기
> 위계로 놓이고, 상태에 따라 무엇이 달라지는가**를 확정한다. 목업 v4는
> 이 문서를 그리는 작업이지, HTML 위에서 구조를 재논의하는 작업이 아니다.
>
> 이 문서가 정하지 않는 것: 시각 디자인 토큰(ui-kit), 액션 상세
> (SCREEN_ACTIONS §3), 데이터 스키마·수집기 계약(w-0vja9), CLI(w-b2v8x).

## 1. 화면 목록 (확정)

| 화면 | 질문 | 리드 |
|---|---|---|
| `VW-ONBOARD` 온보딩 (2단계) | 시작할 준비가 됐나 | 단계 자체 |
| `SH-RESEARCH` 리서치 — **메인 화면** | 다음 가설을 어떻게 만드나 | 터미널 |
| `SH-TODAY` 오늘 | 내 전략들에 무슨 일이 있나 | 전략 목록 |
| `SH-USER` 내 배치 n | 구성한 pane들이 답한다 | 사용자 지정 |

"첫 실행 화면"은 별도 항목이 아니다 — 리서치 프리셋의 **빈 단계**다(§5).
등록·결과 리포트·검증 기록 등은 화면이 아니라 pane으로, 위 화면들 안에
PLACE된다(개체 목록은 SCREEN_ACTIONS §2가 정본).

## 2. 헤더 — 고정 크롬

모든 화면에서 불변. pane이 아니므로 화면의 리드를 뺏지 않는다.

```
┌────────────────────────────────────────────────────────────┐
│ trdr   [리서치] [오늘] [내 배치+]   KOSPI 2,634.2 ▲ KOSDAQ 771.4 ▼  장중 │
└────────────────────────────────────────────────────────────┘
```

| 요소 | 내용 |
|---|---|
| 탭 | 리서치 · 오늘 · 내 배치. **상태와 무관하게 항상 표시** — 등록 0건이어도 오늘 탭은 있다 |
| 지수 스트립 | KOSPI·KOSDAQ 현재 지수와 등락. 시장 정보이므로 시장색 규칙 적용 |
| 장 상태 | 장전 · 장중 · 마감 |

- KIS 수집기 미연결이면 지수 스트립 자리에 "KIS 연결 시 표시" 한 줄 —
  연결할 이유의 상시 노출.
- 온보딩 직후 헤더에 지수가 실제로 뜨는 것이 "연결이 됐고 데이터가
  흐른다"의 증명이다. 현재가는 실시간이라 백필을 기다리지 않는다.
- 주요 종목 현재 수치는 헤더가 아니라 **목록 pane의 소스 하나**다
  ("시장 주요 종목" 소스, `목록` 명령으로 호출).

## 3. 온보딩 — 2단계로 끝난다

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 1/2 수집기 연결 | 설치된 수집기 목록을 렌더링. 각 수집기가 이름·수집 데이터·자격증명 필드를 선언하고 화면은 그린다 | 키 등록 또는 **스킵** |
| 2/2 데이터 셋업 | 기본 제공 데이터셋 표시(자동 포함, 선택 아님) + 백필 시작 명령 1개 | 셋업 실행 **시작** |

내장 수집기 3개 — 전부 API Key 방식, keychain 저장 전용:

| 수집기 | 수집 데이터 |
|---|---|
| KIS | 시세·실시간 (웹소켓 ~41슬롯) · 수급(연결 시점부터 축적) |
| DART | 공시 |
| 금융위 | 보조 데이터 |

- **KRX는 공식 채널이 아니다** (결정 01kzdr2d) — id/pw 로그인 채널은
  공식 지원하지 않는다. 수집은 플러그인 표면이고(결정 01kzdr99) 내장
  3개도 같은 표면 위의 플러그인이다 — 서드파티 수집기를 설치하면 이
  화면에 자동으로 나타난다. 플러그인은 자격증명 필드를 선언만 하고
  값은 trdr가 keychain으로 일원화한다.
- 백필 완료는 온보딩의 책임이 아니다 — 진행률은 수집 상태 pane이
  이어받는다. 위저드에 잡아두면 이탈 지점이 된다.
- "에이전트 연결"은 위저드 단계가 아니다. BYO라 앱이 확인할 연결 상태가
  없다 — 확인 불가능한 단계는 완료 조건이 없는 가짜 단계다. 착지한
  터미널의 첫 줄이 에이전트 실행 안내를 대신한다.

## 4. 성장 규칙 — 미리 깔지 않는다

**빈 pane을 미리 놓지 않는다. 작업이 pane을 놓는다.** (결정 01kzdwff)

- 화면에 보이는 모든 pane은 항상 자기 질문에 답하고 있다 — 리드 규칙
  위반이 구조적으로 불가능해진다.
- pane 배치 모델(치면 나타난다)을 첫 세션이 실제 동작으로 가르친다.
- 빈 상태 공통 규칙: 카탈로그 pane의 빈 상태는 **그 pane을 채우는 행동
  한 줄**을 보여준다. "비어 있습니다"류 상태 서술 금지.

## 5. 리서치 프리셋 — 메인 화면

### 5.1 빈 단계 (온보딩 착지 = 첫 화면)

| pane | 역할 |
|---|---|
| 터미널 (리드) | 에이전트가 먼저 말을 건다 — 첫 가설 만들기 안내 + 에이전트 실행 안내 |
| 수집 상태 | 백필 진행률 — 언제부터 백테스트 가능한가 |

성장 순서 — 작업이 진행되며 완성형에 도달한다:

| 시점 | 추가되는 pane | 경로 |
|---|---|---|
| 에이전트가 스펙 작성 | 스펙 | 파일 저장 시 자동 PLACE |
| 차트가 필요한 시점 | 차트 | 티커 입력 · 에이전트 |
| 첫 백테스트 실행 | 백테스트 | RUN 결과 도착 |

### 5.2 완성형 배치

```
┌─────────────────────────┬──────────────┐
│ 스펙                     │              │
├─────────────────────────┤  터미널 (리드) │
│ 차트                     │  세로 전면    │
├─────────────────────────┤              │
│ 백테스트                  │              │
└─────────────────────────┴──────────────┘
```

- 크기 위계: 터미널 ≈ 폭 40%, 좌열 3개 균등.
- 터미널이 리드인 근거: 화면의 질문 "다음 가설을 어떻게 만드나"의 답은
  에이전트의 지금 작업이다.
- 좌열은 산출 순서(스펙 → 차트 → 백테스트)대로 위→아래 — 빈 단계의
  PLACE 순서와 배치가 일치한다.

### 5.3 백테스트 pane의 보기 방식 — 리플레이 지평 뷰

과거 한 시점을 "그때 등록했다면"으로 잡고, 이후 **1일 · 7일 · 1개월 ·
1년** 지평별 리플레이 성적을 본다 (결정 01kzdxng). 결정론 리플레이
엔진의 화면 대응이다.

## 6. 오늘 프리셋 — 등록 전략의 소비 화면

### 6.1 배치

```
┌──────────────────────────────────────┐
│ 전략 목록 (리드 — 도착한 결과 최상단)     │
├────────────┬────────────┬────────────┤
│ 오늘 볼 종목 │ 수급        │ 공시        │
└────────────┴────────────┴────────────┘
```

- 크기 위계: 전략 목록 ≈ 세로 45% 이상, 하단 3개 균등.
- 전략 목록 행 클릭 → 하단 pane 하나에 관찰 pane이 SWAP.

### 6.2 전략 목록 행과 관찰 pane의 내용

| 표면 | 내용 |
|---|---|
| 전략 목록 행 | 가상 보유 요약 · 누적 수익률 · 종료까지 남은 날 · 도착한 판정 |
| 관찰 pane | **가상 포지션 상태** — 규칙이 시켰을 보유 종목, 매도한 종목, 등록 이후 누적 수익률 |

- **갱신은 일 단위 사후 리플레이다. 장중 실시간 손익은 v0에 없다**
  (결정 01kzdxng). 이 화면의 질문은 "내 전략이 진짜인가"지 "지금 얼마
  벌었나"가 아니다 — 판정에 필요한 것은 종가 기준 성적이고, 장중
  흔들림은 소음이다. 실시간 추적은 실매매 연결과 같은 층으로 v0 밖.

### 6.3 등록 0건일 때

전략 목록 pane 하나가 리드. 헤드라인은 상태가 아니라 행동 — "아직
검증한 전략이 없습니다 — 리서치에서 첫 가설을 만드세요" + 리서치로
가는 액션.

## 7. 순환 플로우와 다리 액션

매일 여는 이유는 검증 루프가 매일 재료를 내놓기 때문이다:

```
가설 만들기 → 백테스트 → 등록 → 매일 관찰 → 판정 도착 ─┐
     ↑                                              │
     └── 판정이 가르쳐준 것이 다음 가설 ─────────────────┘
```

전략마다 생애 단계가 다르다 — 연구 중 · 관찰 중 · 판정 도착이 동시에
걸쳐 있는 것이 정상 상태다. 사용자의 축적 자산은 전략 1개가 아니라
**검증 기록** — 통한 것과 깨진 것 모두.

순환을 화면 동선으로 닫는 다리 액션 2개 (SCREEN_ACTIONS 액션 표에 추가):

| 다리 | 액션 | 방향 |
|---|---|---|
| 생산 → 소비 | 백테스트 pane에 "이 스펙으로 등록" | 리서치 → 등록 → 오늘에 행 생성 |
| 소비 → 생산 | 결과 리포트에 "이 결과에서 새 가설" | 판정 → 리서치 |

에이전트는 새 가설을 만들 때 검증 기록을 CLI로 읽는다(PRD §6.2) —
기록 pane은 부속이 아니라 축적 자산의 표면이다.

## 8. 2화면 분리 근거 (결정 01kzdxn9)

| # | 근거 |
|---|---|
| 1 | **수정 가능 vs 동결**: 리서치의 스펙은 고치는 대상, 등록 전략은 동결 대상. 사전등록 규율의 경계가 화면 경계다. 등록 확정 → 저쪽 화면에 행이 생기는 전환이 눈에 보이는 의식이 된다 |
| 2 | **질문이 다름**: 한 화면에 리드는 하나 — 합치면 리드가 둘이 된다 |
| 3 | **리듬이 다름**: 전략 점검은 아침 몇 분, 연구는 몇 시간 세션 |

경계는 벽이 아니다 — 프리셋은 기본 구성 2벌이고, `전략` 한 줄이면
전략 목록을 리서치에 놓을 수 있다.
